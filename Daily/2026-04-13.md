### Project: Clowder ScaledObject Bug

Successfully reproduced the ScaledObject `serverAddress` reconciliation bug end-to-end in minikube.

**Bug summary:** When a ClowdApp specifies a `serverAddress` in its prometheus autoscaler trigger metadata, Clowder silently ignores it and always uses the ClowdEnvironment's `env.Status.Prometheus.ServerAddress` instead. Reconciliation reports success, but the ScaledObject never reflects the ClowdApp's value.

**Root cause:** `controllers/cloud.redhat.com/providers/autoscaler/keda.go:101` — `getTriggerRoute("prometheus", ...)` unconditionally sets `result["serverAddress"] = env.Status.Prometheus.ServerAddress`, and the merge loop at lines 72-74 overwrites whatever the ClowdApp specified.

**Steps taken to reproduce:**

1. Built and deployed Clowder from `scaledobject-reconcile` branch to minikube
   - Used `podman save | docker load` workaround (minikube registry addon has connection issues)
   - Applied `clowder-config.yaml` with `enableKedaResources: true` to `clowder-system` namespace and restarted controller
2. Created a ClowdEnvironment (`test-so-bug`) with `metrics.mode: app-interface` and `appInterfaceInternalURL: https://env-level-prometheus.example.com:9090`
3. Deployed a simplified ClowdApp with a prometheus autoscaler trigger specifying `serverAddress: https://app-level-custom-prometheus.example.com:9090`
4. Verified: ScaledObject got `https://env-level-prometheus.example.com:9090` (env value, not app value)
5. Updated ClowdApp serverAddress to `https://updated-app-prometheus.example.com:9090` and re-applied
6. Verified: ScaledObject still shows env-level value, reconciliation reported `ReconciliationSuccessful: True`

**Key finding:** The ClowdApp's `serverAddress` is always overwritten — this is not a timing or caching issue, it's the designed code path. The `getTriggerRoute` function is intentionally injecting env-level values over app-level values.

**Fix implemented and verified:**

Changed the merge loop in `keda.go:72-74` from unconditional overwrite to "set if not present":
```go
// Before:
for k, v := range triggerType {
    trigger.Metadata[k] = v
}

// After:
for k, v := range triggerType {
    if _, exists := trigger.Metadata[k]; !exists {
        trigger.Metadata[k] = v
    }
}
```

This ensures app-level trigger metadata takes precedence. If the ClowdApp doesn't set a field, the env-level value fills in as a default.

Added kuttl test `test-autoscaler-prometheus-app-serveraddress/` that verifies:
1. App-specified `serverAddress` is preserved (not overwritten by env value)
2. Updating the app-level `serverAddress` propagates to the ScaledObject

**Verification results:**
- Built and deployed fixed Clowder to minikube
- Manual check: `test-so-bug` namespace ScaledObject now correctly shows the app-level serverAddress
- New kuttl test: PASS
- Existing tests (`test-autoscaler-prometheus-app-interface`, `test-autoscaler-prometheus-status-only-update`): PASS — no regressions
