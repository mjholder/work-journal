- [org-pulse] **Important correction to the porting method — ENGPROD-10381's import-rewrite guidance does not apply to `hp-org-pulse`.** That ticket prescribes rewriting server requires from `require('../../../shared/server/jira')` to `require('@shared/server').jira`. In `hp-org-pulse` that would break at runtime: `@shared` is a **bundler-only** Vite/Vitest resolve alias, and neither `hp-org-pulse` nor `@org-pulse/core` declares an `imports` map — `node -e "require.resolve('@shared/server')"` returns `MODULE_NOT_FOUND`. What actually makes the relative paths work is `scripts/setup.js`, which symlinks `shared/server` and `shared/client` out of `@org-pulse/core` into the repo root (and `shared` is gitignored, so it only exists after `npm run setup`). **The ports are therefore straight copies with no import changes** — which makes all four tickets meaningfully cheaper than the epic implies. Wrote this into each ticket explicitly so nobody "modernises" the imports and breaks the server.
