### Project: Matomo Analytics Fix

Investigated why matomo analytics stopped tracking visits after the backstage upgrade. The upgrade changed the matomo plugin from `@janus-idp/backstage-plugin-analytics-module-matomo@1.3.1` to the community version `backstage-community-plugin-analytics-module-matomo:bs_1.45.3__1.22.0` via the `rhdh-plugin-export-overlays` OCI registry.

**Root cause identified:** The `rhdh-plugin-export-overlays` repo is missing the overlay directory for the matomo plugin. The plugin is listed in `plugins-list.yaml` but has no corresponding `plugins/analytics-module-matomo/` directory (unlike GA4, NewRelic, and Segment which all have one).

**Key findings from deep investigation:**

1. **Symptoms:** Plugin loads in scalprum (confirmed in pod logs), POST requests return 200 with `{"success":true,"message":"Event received"}`, but no visits tracked in matomo and no matomo pod logs. The 200 responses were coming from backstage's own analytics framework, not matomo.

2. **Browser confirms no matomo initialization:** `typeof _paq` and `typeof Matomo` both return `undefined` - the matomo.js tracking script is never injected into the page.

3. **OCI package inspection:** Extracted the OCI artifact and found:
   - `dist-scalprum/plugin-manifest.json` has `"extensions": []` - scalprum has nothing to auto-register
   - The `PluginRoot` chunk exports `MatomoAnalyticsApi` (a `createApiFactory`) and `analyticsModuleMatomoPlugin` (a `createPlugin` with no extensions) - these are **legacy-style** exports
   - The `dist/` directory has an **alpha export** that uses `AnalyticsImplementationBlueprint.make()` (new frontend system) with proper extensions, but scalprum doesn't use `dist/`, it uses `dist-scalprum/`

4. **Comparison with working GA4 plugin:** The GA4 plugin has three files in its overlay directory that matomo is missing:
   - `scalprum-config.json` - tells scalprum what module to expose as PluginRoot
   - `overlay/src/api.ts` - re-exports the API factory with a named export
   - `app-config.dynamic.yaml` - includes `dynamicPlugins.frontend` config with `apiFactories` registration

5. **Previous config removal was not the cause:** The old `dynamicPlugins.frontend.janus-idp.backstage-plugin-analytics-module-matomo.apiFactories` config was removed before the plugin upgrade. With the old Janus plugin, this was required. With the new community plugin, using the old Janus plugin name would fail anyway.

6. **Config updates deployed to stage (not the fix but good to have):**
   - Added `enhancedTracking: true`, `identity: optional`, `deferInitialPageView: true` to matomo config
   - Added `connect-src` to CSP configuration (was missing per upstream docs)

**Fix approach:** Contribute the missing overlay directory to `rhdh-plugin-export-overlays`:
- Repo: https://github.com/redhat-developer/rhdh-plugin-export-overlays
- Location: `workspaces/analytics/plugins/analytics-module-matomo/`
- Need: `scalprum-config.json`, `overlay/src/api.ts`, `app-config.dynamic.yaml`
- Follow exact same pattern as `plugins/analytics-module-ga4/`
- The `app-config.dynamic.yaml` should use `backstage-community.plugin-analytics-module-matomo` as the plugin name with `apiFactories: [{importName: MatomoAnalyticsApi}]`
