##### Demo outline — new `hp-org-pulse` repo architecture
1. **Upstream is org-pulse core.** We're starting from the team-agnostic version, not a fork of the RHAI repo. No RHAI CI jobs or RHAI-specific modules come along with it — that's what made the old setup difficult to work in.
   - **Core is a dependency, not a git relationship.** There's no remote pointing at `org-pulse-core` — nothing to rebase or merge. Upgrading core is a version bump. Best illustration: `src` is a *symlink* into `node_modules/@org-pulse/core/src`. The platform isn't vendored into our tree at all.
   - **It's two surfaces, both on `v2.0.90` today:** `@org-pulse/core: ^2.0.90` in `package.json`, and three `FROM quay.io/org-pulse/org-pulse-core-*:v2.0.90` pins across `deploy/hp-eng.{backend,frontend}.Dockerfile`.
   - **Gotcha if asked:** `renovate.json` groups npm deps and container images *separately*, so a core release shows up as two Mintmaker PRs. Merge one without the other and npm core drifts from container core. `scripts/validate-dockerfile-deps.js` won't catch it — it validates the `npm install --no-save` lists and skips core. `:disableMajorUpdates` also means a core v3 is a manual bump.
2. **Modules are ours (and our partners').** Walk through the modules we've written, plus the ones contributed by the other teams we're working closely with.
3. **Live run.** Show it running locally.
4. **Repo structure.**
   - `modules/` — our custom modules
   - `fixtures/` — test data only, for local runs
   - testing/CI — two things worth saying:
     - **Change-driven matrix.** Only modules you touched get tested — one job each, in parallel, `fail-fast: false` so a broken module doesn't mask the others. The `integration-test-status` gate exists so there's one required check to pin in branch protection even when the matrix comes up empty.
     - **Containers, not a dev server.** Tests run against the actual built frontend/backend images in `DEMO_MODE=true`, so the fixtures are the data under assertion. Same `make test-module` locally as in CI.
5. **Where this is going.** Red Hat–wide, there will be a single tenancy-based org-pulse instance (built by another team, not us). All of our modules port over to it, and modules get toggled on/off per tenant.
