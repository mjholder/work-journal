### Research: Agentic AI & Hackathon Prep

Explored agentic AI concepts and designed an architecture for a security ticket automation tool (hackathon project).

**Key takeaways:**

- Agentic AI = LLM in a loop with tools, taking actions toward a goal (observe → think → act)
- The practical pattern for production workflows: **LLM sandwiched between deterministic code**
  - Your code handles: API auth, data fetching, ticket creation, scheduling
  - Claude handles: the messy part — parsing inconsistent human-written ticket descriptions, extracting package/version info, grouping by application

**Architecture for security ticket tool:**

```
[Cron] → [Python Script]
              │
              ├── 1. JIRA API: fetch security tickets via JQL (deterministic)
              ├── 2. Claude API: analyze & group tickets, extract package/version data (LLM)
              ├── 3. Validate/format Claude's JSON response
              └── 4. JIRA API: create summary ticket, assign to team
```

**Getting structured JSON from Claude:**

- Use **tool use** with `tool_choice` to force Claude to return data matching a specific JSON schema
- Define a tool with `input_schema` describing the exact structure you want (app name, packages, versions, CVEs, ticket keys)
- This is more reliable than just asking for JSON in the prompt — the SDK guarantees the structure
- `tool_choice={"type": "tool", "name": "your_tool"}` forces Claude to use that tool

**Retry pattern for validation:**

- Wrap Claude call in a retry loop (max 3 attempts)
- On failure, feed the validation error *back* to Claude so it self-corrects rather than just re-rolling
- With tool use approach, JSON parse failures are rare — mainly validating business logic (missing tickets, plausible version strings)

**Tech stack:** Python + `anthropic` SDK + `jira`/`requests` library
