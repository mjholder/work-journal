##### From-scratch sandbox image build (alternative to overlay approach)

If the overlay approach breaks (upstream changes cache path structure, plugin format, or user/directory layout), here's what a from-scratch build would require. Bounce this off the team to see if it's worth pursuing proactively.

**What the upstream image does (two-layer build in `opendatahub-io/agentic-ci`):**

1. **Layer 1 — openshell-base** (`images/runner/shared/Containerfile.openshell-base`):
   - Base: `registry.access.redhat.com/ubi10/ubi-minimal:10.2`
   - Installs: python3, git, curl, jq, make, tar, xz, iproute, shadow-utils, uv, gh CLI, glab CLI, shellcheck, ruff
   - Installs the `agentic-ci` Python package from source (needed for `enable-plugins` at runtime)
   - Creates a `sandbox` user (uid 998) at `/sandbox`
   - Copies `entrypoint.sh` and `AGENTS.openshell.md`

2. **Layer 2 — claude-sandbox** (`images/runner/claude-code/Containerfile.openshell`):
   - Adds nodejs + npm
   - Downloads Claude Code CLI (pinned version with SHA256 check, currently v2.1.186)
   - Runs `claude plugin marketplace add opendatahub-io/skills-registry` to register the plugin marketplace
   - Runs `agentic-ci install-plugins` which loops through the marketplace and `claude plugin install`s each plugin (git clones into `/sandbox/.claude-seed/cache/`)
   - Sets env vars: `CLAUDE_CODE_PLUGIN_SEED_DIR`, `CLAUDE_CODE_SYNC_PLUGIN_INSTALL`, `DISABLE_AUTOUPDATER`, `AGENT_TOOL`

**To replicate this for our fork, we'd need to:**

1. Fork `opendatahub-io/agentic-ci` (or write our own Containerfile from ubi-minimal)
2. Maintain Claude Code CLI version pinning ourselves (check for updates, update SHA256)
3. Either:
   - Fork `opendatahub-io/skills-registry` and change the assess-rfe entry to point at `RedHatInsights/assess-rfe`, then use the same marketplace flow
   - Or skip the marketplace entirely and manually set up the plugin cache, `installed_plugins.json`, `known_marketplaces.json`, `settings.json` (enabledPlugins), and `plugin-skills.manifest.json`
4. Replicate `entrypoint.sh` (which calls `agentic-ci enable-plugins` at startup to toggle plugins on/off based on `AGENT_ENABLED_PLUGINS` env var)
5. Keep the `agentic-ci` Python package in sync (it provides the `enable-plugins` and `install-plugins` CLI commands)

**What we'd own and maintain:**
- Claude Code CLI version + SHA256 updates
- System deps (python3, nodejs, npm, git, gh, glab, etc.)
- `agentic-ci` Python package updates (or our own fork of it)
- `entrypoint.sh` behavior
- Plugin registration files

**Simplest from-scratch variant:** Fork the skills-registry (one JSON file change to point assess-rfe at our repo), then copy the upstream Containerfiles mostly as-is. This minimizes what we have to maintain while giving full control. The main ongoing cost is keeping Claude Code CLI pinned to a working version.

**When to pull this trigger:** The overlay approach (`FROM claude-sandbox:latest` + COPY) is working today and verified locally. Switch to from-scratch if/when the upstream image changes break the overlay (skill doesn't load, path structure changes, user/permissions change).
